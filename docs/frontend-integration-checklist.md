# 前端与 Java 后端联调清单

## 使用范围

本清单只覆盖前端页面和既有 HTTP 接口的兼容性验收。

- 前端负责：按本清单发起请求、核对页面行为、记录结果。
- Java 后端负责：保持接口路径、请求字段、响应结构和权限语义兼容。
- 本清单不要求修改 `backend/`、`backend-java/` 或 `database/`。

## 当前 Java 兼容差异（2026-09-07）

以下内容以旧 Node 后端的实际行为为准。Java 后端完成这些项后，旧前端和旧客户端才能视为完全兼容。

| 接口 | Java 当前差异 | 旧 Node 契约与待修正项 | 前端当前处理 |
| --- | --- | --- | --- |
| `PUT /api/drafts/:id` | 不存在草稿或已发布草稿的状态码、错误行为未完全对齐 | 不存在、无权访问或状态不是 `draft` 时，返回 HTTP `404` 和 `{ "success": false, "message": "草稿不存在或无权修改" }` | 正常显示后端错误信息；等待 Java 对齐 |
| `POST /api/drafts/:id/publish` | 当前返回 HTTP `200` 和 `{ "slug": "..." }` | 成功时返回 HTTP `201` 和 `{ "success": true, "data": { "articleId": 文章数字 ID } }`；不合法内容返回 `400`；草稿不存在、无权或已发布时返回 `404` | 优先使用 `articleId` 跳转详情；仅有 `slug` 时跳转归档页，避免进入可能不支持 slug 的详情接口 |

Java 后端应在发布成功时同时保留 `articleId`，如需保留 slug，可扩展为：

```json
{
  "success": true,
  "message": "文章已发布",
  "data": {
    "articleId": 123,
    "slug": "example-article-123"
  }
}
```

## 问题记录规范

每一个失败项记录以下内容，方便对方直接定位：

1. 测试时间和测试账号。
2. 页面地址与复现操作。
3. 请求方法、请求地址、请求参数或请求体。
4. HTTP 状态码和完整响应体。
5. 浏览器控制台错误或网络面板截图。
6. 期望行为与实际行为。

## 联调完成标准

- 第一批必须可用的接口全部通过。
- 首页、归档页、创作台、文章页和数据分析页的关键流程均通过。
- 所有失败项都明确归属为前端问题、Java 后端问题、数据库数据问题或部署配置问题。
- 修复后在本清单中复测并标记通过。
